# WorldsLab

A NimbleEngine game, made by the editor's **File > New Project** (or
`Engine/Binaries/NewProject.sh` / `.bat`) from `Engine/Templates/Game`. `Games/Sandbox` is the full example to follow.

New here? Start with [Docs/GettingStarted.md](Docs/GettingStarted.md).

## Build and run

```
cmake --preset editor-debug
cmake --build --preset editor-debug
```

Then run `Binaries/<Platform>_Debug/NimbleEditor` to edit the game, or
`Binaries/<Platform>_Debug/WorldsLab` to play it. `client-*` presets build
the game alone, without the editor.

## Layout

| Path | What |
|------|------|
| `WorldsLabGame.cpp` | The game module: level, game mode, game state, native prefabs |
| `Config/DefaultEngine.ini` | Settings; `[Game]` names the module and start level |
| `Scripts/` | Lua and script graphs; `Main.lua` runs on every level load |
| `Content/Materials/` | Material graphs (`File > New Material Graph`) |
| `Content/Prefabs/` | Prefabs (`File > New Prefab`) |
| `Content/Levels/` | Worlds saved from the editor |
| `Content/Meshes/`, `Content/Textures/` | Imported assets |
| `Docs/` | This project's guides |
| `Tools/<Style>/` | The Python generators that build each style's world and content |
| `WorldsLabExplore.cpp` | The style worlds' game mode: walk (with collision) and fly |

Everything in `Config/`, `Scripts/` and `Content/` is staged into `Binaries/`
by the build at the same relative path, which is how the runtime names it
(`Content/Prefabs/Door.nmprefab`). A new C++ file goes in `CMakeLists.txt`'s
`nimble_add_hot_module` list. The `WorldsLab` executable is the engine's
launcher (`nimble_add_game_launcher`); there is no `main()` to maintain.

## Worlds

WorldsLab tries visual styles: each style is a world, generated by a script
in `Tools/<Style>/` into `Content/<Kind>/<Style>/`, listed in Project Settings >
Worlds and run by the `WorldsLabExplore` mode.

### Steampunk Street Corner (`SteampunkStreet`)

`Content/Levels/Steampunk/SteampunkStreet.nmworld` -- the editor's startup
world. Photoreal, late afternoon: two city blocks (1 x 2) of Victorian
shop-houses round cobbled streets, the cross street making two four-way
intersections, a clock tower on the corner where you start. Gas lamps, tram
rails, steam grates, a boiler, an airship overhead; low sun, a hazy HDRI sky,
volumetric haze, SSR on the wet cobbles.

Walk with WASD and the mouse (Shift runs). F toggles flying (E/Q up and down).
Escape frees the mouse; a click takes it back. Buildings and props are solid:
every entity with a Bounds component is a wall.

Everything is procedural, and regenerating it rewrites the same files. Run
these from the repository root, after one `editor-debug` build, because the
material scripts use its `NodeGraphGenerate`:

```
python Games/WorldsLab/Tools/Steampunk/make_steampunk_textures.py    # Content/Textures/Steampunk (PBR sets, dials, sky)
python Games/WorldsLab/Tools/Steampunk/make_steampunk_materials.py   # Content/Materials/Steampunk
python Games/WorldsLab/Tools/Steampunk/make_steampunk_street.py      # meshes, prefabs, particles, post process, the world
```

| Script | Makes |
|--------|-------|
| `nmformats.py` | Shared: writes `.nmtexture`, `.nmmesh`, and `.nmentity` files |
| `steampunk_kit.py` | The meshes: facades, shopfronts, roofs, clock tower, lamps, props |
| `make_steampunk_textures.py` | 13 tileable PBR sets (BaseColor, Normal, ORM), the clock and gauge dials, the sky HDRI |
| `make_steampunk_materials.py` | Material graphs. Texture tiling is the `UVScale` parameter, because mesh UVs are in metres. Base colour is multiplied by vertex colour (baked grime). Vertex alpha is wetness |
| `make_steampunk_street.py` | The layout, lights, probes, `Street.pp.nmgraph`, `GasLamp` and `SteamVent` prefabs, `Steam` and `ChimneySmoke` particles |

Edits made in the editor are kept until the street script runs again, which
rewrites the world.

### Shooting Range (`ShootingRange`)

`Content/Levels/ShootingRange.nmworld`, run by `WorldsLabRange` (`WorldsLabRange.cpp`).
A gritty steel-framed warehouse, 30 x 50 m, the midday sun shafting through
two rows of wired skylights into dusty air, fluorescent tubes over a
staging area. A six-lane range runs down the middle: plywood booths and a
bench at the firing line, block side walls, overhead baffles, a sloped rubber
backstop. Hinged AR500 steel plates (14 and 22 m) swing and ring when hit;
paper silhouettes stand at 18 m. Stairs climb the west wall to a
diamond-plate mezzanine and railed, grated catwalks along both walls and
twice across the range, 4.5 m up.

You play the **RangeShooter** (`Content/Prefabs/ShootingRange/RangeShooter.nmprefab`):
the engine's crash dummy and its pistol, third person. The Player Start
spawns it (an `NetGameMode`); `RangeMove`, an avatar simulation, walks it on
the physics with raycasts -- floors, stairs, catwalks, walls -- and swings the
camera. `Scripts/ShootingRange/RangeShooter.lua` draws and holsters (the
pistol moves between holster and hand on the clips' notifies), shoots
(Physics.Raycast through the crosshair; steel gets an impulse, sparks and a
ring; rounds pass the catwalk grating), reloads, and feeds the HUD
(`Content/UI/ShootingRange/RangeHUD.nmui`: rounds, reserve, hits, shots,
accuracy, crosshair).

WASD walks (Shift runs), Space jumps, H draws, right mouse scopes in (the
camera slides in over the shoulder, the view narrows to 40 degrees, the look
slows), left mouse fires, R reloads, Escape frees the mouse. `[WorldsLab] RangeAutoPlay=1` makes
it play itself -- shoot from the line, reload, climb to the catwalk, shoot
down range -- through the avatar input filter.

Needs JoltPhysics (`[Modules] JoltPhysics=true`, on for this project): the
shell, range and props are static triangle meshes on layer 1; the stairs,
catwalks and railings are invisible boxes on layer 2, walked on and shot
through. Regenerate from the repository root, after an `editor-debug` build:

```
python Games/WorldsLab/Tools/ShootingRange/make_range_textures.py    # Content/Textures/ShootingRange (PBR sets, sky)
python Games/WorldsLab/Tools/ShootingRange/make_range_materials.py   # Content/Materials/ShootingRange (and Grit, the grade)
python Games/WorldsLab/Tools/ShootingRange/make_range_level.py       # meshes, prefabs, particles, post process, the world
python Games/WorldsLab/Tools/ShootingRange/make_range_sounds.py      # Tools/ShootingRange/Audio/*.wav, then import them
```

The sounds import with the editor's console (`import Tools/ShootingRange/Audio/Gunshot.wav
Content/Sounds/ShootingRange`, one a file). Reflection probes are off
(`PROBES` in the level script) until they stop mirroring onto the shooter.

### Courtyard (`Courtyard`)

`Content/Levels/Courtyard.nmworld`, brought over from LightLab: a Spanish
Colonial Revival house round a cloister at sunset -- stucco walls, a tiled
fountain, an arcade, a great hall with a hearth. Baked lighting
(`Content/Levels/Courtyard/Lighting/`), shadowed lanterns and chandeliers.
Its mode, `WorldsLabCourtyard`, is the explore mode plus the hearth's flicker,
four shadowed point and spot lights, and sun contact shadows while it runs.
The house has no Bounds, so walking passes through its walls.

```
python Games/WorldsLab/Tools/Courtyard/make_courtyard_textures.py    # Content/Textures/Courtyard
python Games/WorldsLab/Tools/Courtyard/make_courtyard_sky.py         # SunsetSky.nmtexture
python Games/WorldsLab/Tools/Courtyard/make_courtyard_materials.py   # Content/Materials/Courtyard
python Games/WorldsLab/Tools/Courtyard/make_courtyard_level.py       # meshes, particles, post process, the world
```

Regenerating the world drops its baked lighting; rebake it in the editor.
